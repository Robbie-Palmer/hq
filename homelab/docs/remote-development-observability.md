# Remote development observability

This runbook covers the external state that the repository cannot create. The
NixOS definition, Netdata rules, and Kubernetes manifests are the source of
truth for the deployed monitoring configuration.

## External services

Create a private, project-owned Slack channel. It needs two integrations:

* an incoming webhook for Netdata; and
* the Healthchecks.io Slack app, added from the Healthchecks.io Integrations
  page and named `remote-development-alerts`.

Healthchecks.io requires interactive Slack authorization. Its Management API
can reconcile the check after the integration exists.

Store the external setup values as masked secrets in
`homelab/prd_remote_development_observability`:

| Secret | Value |
| --- | --- |
| `NETDATA_SLACK_WEBHOOK_URL` | Slack incoming webhook URL |
| `HEALTHCHECKS_API_KEY` | Project-scoped read-write Healthchecks.io API key |
| `HEALTHCHECKS_PING_URL` | Generated by the reconciliation task |

Enter the webhook and API key interactively so they do not appear in shell
history:

```bash
doppler secrets set NETDATA_SLACK_WEBHOOK_URL \
  --project homelab \
  --config prd_remote_development_observability \
  --visibility masked
doppler secrets set HEALTHCHECKS_API_KEY \
  --project homelab \
  --config prd_remote_development_observability \
  --visibility masked
```

Do not include usernames, source paths, pod logs, or repository data in alert
text.

Reconcile the Healthchecks.io check, install the runtime secrets on the host,
and run the health check:

```bash
mise run //homelab:remote-healthchecks-reconcile
mise run //homelab:remote-observability-credentials
mise run //homelab:remote-health
```

The reconciliation task is idempotent. It upserts the check by slug, attaches
the named Slack integration, and stores the returned ping URL without printing
it. Run all three tasks again after replacing the host. The credential task
sends the first heartbeat so the check can leave its new state.
