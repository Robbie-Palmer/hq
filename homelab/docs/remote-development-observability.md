# Remote development observability

This runbook covers the external state that the repository cannot create. The
NixOS definition, Netdata rules, and Kubernetes manifests are the source of
truth for the deployed monitoring configuration.

## External services

Create a private, project-owned Slack channel. It needs two integrations:

* an incoming webhook for Netdata; and
* the Healthchecks.io Slack app, added from the Healthchecks.io Integrations
  page and named `remote-development-alerts`.

Healthchecks.io requires interactive Slack authorization. Its Management API
can reconcile the check after the integration exists.

Store the external setup values as masked secrets in
`homelab/prd_remote_development_observability`:

| Secret | Value |
| --- | --- |
| `NETDATA_SLACK_WEBHOOK_URL` | Slack incoming webhook URL |
| `HEALTHCHECKS_API_KEY` | Project-scoped read-write Healthchecks.io API key |
| `HEALTHCHECKS_PING_URL` | Generated by the reconciliation task |
| `POSTHOG_PROJECT_TOKEN` | Ingestion token for the shared PostHog EU project |

Enter the webhook, API key, and project token interactively so they do not
appear in shell history:

```bash
doppler secrets set NETDATA_SLACK_WEBHOOK_URL \
  --project homelab \
  --config prd_remote_development_observability \
  --visibility masked
doppler secrets set HEALTHCHECKS_API_KEY \
  --project homelab \
  --config prd_remote_development_observability \
  --visibility masked
doppler secrets set POSTHOG_PROJECT_TOKEN \
  --project homelab \
  --config prd_remote_development_observability \
  --visibility masked
```

Do not include usernames, source paths, pod logs, or repository data in alert
text.

Reconcile the Healthchecks.io check, install the runtime secrets on the host,
and run the health check:

```bash
mise run //homelab:remote-healthchecks-reconcile
mise run //homelab:remote-observability-credentials
mise run //homelab:remote-health
```

The reconciliation task is idempotent. It upserts the check by slug, attaches
the named Slack integration, and stores the returned ping URL without printing
it. Run all three tasks again after replacing the host. The credential task
sends the first heartbeat so the check can leave its new state.

Netdata also checks `remote-development-agent-coordinator.service` and the
coordinator's last reconciliation timestamp when the NixOS configuration
enables it. A declared pause suppresses the service and admission alarms. An
enabled service is unhealthy if its status file is more than three minutes
old, malformed, violates its three-ticket concurrency ceiling, or exceeds its
12-ticket pilot budget. The
`operator_agent_coordinator` chart records owned tickets and the subset waiting
for human input. The service chart records whether the resource admission gate
is open, and Netdata warns when it stays closed for ten minutes. These metrics
contain no ticket titles or agent output.

## T3 Code telemetry

Use the existing shared PostHog EU project. Remote-development records carry
`deployment.environment.name=remote-development`; current workspace records
also carry `workspace.id=operator`. Treat those properties as the boundary
between this telemetry and the personal site, recipe site, asset tracker, and
other applications in the project.

Configure the shared project before installing its token:

* retain traces and logs for no more than 30 days;
* send billing notices at 50, 80, and 100 percent of the agreed monthly limit,
  with the account-level hard limit enabled where the plan supports it;
* use the project-owned Slack destination for matching alerts;
* create a `Remote development / Workspace operations` dashboard with provider
  turns by outcome, provider latency, provider failures, and terminal lifecycle
  panels;
* prefix its saved insights and alerts with `Remote development /`; and
* alert Slack when three or more failed provider turns occur for `operator`
  within ten minutes, with a recovery notification after ten quiet minutes.

Every dashboard panel, saved insight, alert, and Slack notification must filter
on `deployment.environment.name=remote-development`. Add
`workspace.id=operator` when the asset concerns the current workspace. Do not
save a shared-project asset for this system without the environment filter.

The host Collector accepts OTLP/HTTP only on the K3s bridge at
`10.42.0.1:4318`. It sends allowlisted T3 metrics to Netdata's loopback
OTLP/gRPC endpoint and sends redacted traces and warning/error markers to
PostHog. All span events are dropped. Trace, metric, resource, and log
attributes use explicit allowlists. Warning and error bodies are replaced with
a fixed string, so an unknown application message cannot leave the host.

T3 Code keeps its rotating local trace file even while OTLP export is enabled.
The local file is the only place where detailed diagnostics may remain. The
public project page contains the notice that must be shown before another
person's workspace is enabled.

A future Kube-Hetzner deployment must run the Collector outside user
namespaces, preserve these default-deny filters and attribute allowlists, and
replace only the declared workspace ID. It must pass the same configuration
validation and exported-record review before a second workspace is enabled.

Netdata alerts on a stopped Collector, newly refused or failed records, and a
sustained exporter queue. Check the local pipeline without exposing the
PostHog token:

```bash
curl --fail http://127.0.0.1:13133/
curl --fail http://127.0.0.1:8888/metrics \
  | grep -E '^otelcol_(exporter|receiver)_'
```

After the shared PostHog configuration is ready, install credentials, deploy
the host and workspace manifests, then exercise one successful provider turn,
one failed turn, and one terminal open/close cycle. Confirm the `operator`
workspace ID in both Netdata and PostHog, confirm every saved PostHog asset has
the environment filter, and verify that unrelated application records do not
appear or trigger the alert. Confirm the local trace file still advances and
review exported records for the forbidden data classes named on the project
page. Stop the Collector once to prove the Netdata failure and recovery alert.
