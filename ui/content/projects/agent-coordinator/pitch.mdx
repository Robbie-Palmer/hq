# Ship the security fix, not another notification

Agent Coordinator turns a severe dependency alert into a verified production
outcome.

<PitchNotes>
  GitHub and Renovate are good at detection and deterministic update proposals. The gap begins when the proposal
  needs application changes, CI repair, a merge decision, rollout supervision, or production QA.

## Renovate proposes. An agent owns the outcome.

<PitchColumns>
  <PitchColumn>

## T3 Code provides the replacement control plane

* Signed webhook automations and replay protection
* Persistent controller threads
* Top-level thread launch with managed worktrees
* Provider sessions and subscription authentication
* Usage-limit monitoring, snooze-until-reset, and automatic continuation
* Recovery of interrupted threads after server or machine restarts
* Pull-request watches that wake agents for checks and reviews

<p className="pitch-slide__statement">Build the security policy and outcome loop on T3 while the current launcher keeps existing work moving.</p>

<PitchNotes>
  The current Work Graph poller, launcher and provider-session package remain useful during the transition. Limit

  do not keep both orchestration paths as permanent fallbacks.

## A controller thread directs the work

The controller admits the alert, finds related work, and launches one worker
that owns the incident.

Later GitHub events return to the controller, which routes them to the same
worker or starts a focused recovery thread.

<p className="pitch-slide__statement">Thread orchestration supplies continuity without one enormous agent session.</p>

<PitchNotes>
  The controller remains small and serial. Workers get isolated worktrees and can fan out research, review or recovery
  when parallel work helps.

  \[Sources]

  * [Controller and worker roles](/projects/agent-coordinator?tab=overview#controller-and-worker-roles)
    \[/Sources]
</PitchNotes>

## The vulnerability workflow starts from events

Webhook events start the work. The controller writes incident transitions,
thread ownership, pull requests, commits, deployments, and validation evidence.

<p className="pitch-slide__statement">Neon receives event-driven state changes instead of constant queries for ready work.</p>

<PitchNotes>
  A low-frequency reconciliation can repair missed evidence. The existing launcher may continue polling general Work
  Graph work during the transition, but the new vulnerability workflow does not depend on that polling loop or on
  Work Graph forwarding the webhook.

## Trust the agent to merge and operate

The initial repositories have no external users. The worker may merge after
required checks, follow the established deployment path, inspect production,
and repair or revert a failed rollout.

It asks for help when it lacks authority or cannot establish a safe result.

<p className="pitch-slide__statement">Use machine-enforced limits without turning every routine decision into an approval.</p>

<PitchNotes>
  The worker cannot weaken branch protection, disable checks or dismiss the alert instead of fixing it. Those controls
  preserve honest evidence while leaving the agent enough authority to create real value.

  \[Sources]

  * [Authority model](/projects/agent-coordinator?tab=overview#authority-model)
    \[/Sources]
</PitchNotes>

## Begin with one hard, measurable outcome

For each admitted alert, the system must either ship and validate a fix or
explain the exact obstacle that prevents one.

<p className="pitch-slide__statement">A production result exposes weak orchestration faster than a queue of generated PRs.</p>

<PitchNotes>
  Severe vulnerability resolution exercises event admission, repository reasoning, code changes, review, merge,
  deployment, QA, recovery and durable evidence in one bounded workflow.

## Start narrow, then coordinate the automatable SDLC

When GitHub finds a serious dependency vulnerability, an agent should carry it
through the last mile and leave behind a healthy deployment and an auditable
record.

Once that loop works, apply the same coordination to delivery failures,
production regressions, codebase analytics and bounded refactoring, and other
work with objective completion checks.
