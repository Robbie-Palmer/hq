# Vision

Keep available agents working on the most useful tasks they can perform, while
letting the Work Graph remain independent of models, subscriptions, machines,
and agent products.

The coordinator answers a different question from the graph. The Work Graph
says what is ready and what constraints apply. The coordinator finds an actor
whose capabilities, interests, authority, budget, and current capacity fit the
task.

# Why this is separate

Model choice changes quickly. Some work needs a frontier model for research or
architecture. Some can run on a cheaper model. Mechanical maintenance may be
suited to a free model. Available capacity also shifts as subscriptions reach
usage limits or a person loses focus.

Putting those details in the Work Graph would couple durable project knowledge
to a temporary market. The graph should keep task complexity, required
capabilities, authority, and evidence. The coordinator should map those needs
to the actors available now.

# Architecture

There is no deployed coordinator yet. Today, an owner or a directly supervised
agent queries the Work Graph, chooses a ready item, and claims its lease. The
Work Graph remains the authority for priority, dependencies, readiness, leases,
attention, and completion evidence. It does not choose an actor or model.

The planned Agent Coordinator sits between that coordination record and a pool
of candidate actors. It will read ready work and owner policy from the Work
Graph, compare task requirements with actor capabilities and availability, and
offer a bounded context package to a suitable actor. People, coding agents, and
project-owned automation are candidate actors. Model providers are external
services that supply models, sessions, prices, and capacity. They do not decide
which work matters, and the coordinator does not receive a contributor's
credentials.

The first routing mode will be advisory. The owner sees the proposed actor and
task before anyone claims a lease. Later automatic routing may claim and renew
leases only inside owner-defined limits for task class, budget, access, and
concurrency. It cannot change Work Graph priority or dependencies, approve an
attention request, or mark work complete without the evidence required by the
graph. Actors return progress and delivery evidence through the Work Graph;
execution telemetry stays outside the public task graph.

The initial routing model can use broad bands. Deep research and architecture
need frontier reasoning. Well-bounded implementation can use mid-priced models.
Mechanical maintenance may fit cheap or free models. The named models will
rotate too quickly to make them part of the durable schema. Evaluation history,
observed task outcomes, current prices, subscription allowances, and available
capacity should drive the mapping.

# Actors

An actor may be a person, an agent directed by that person, or an agent running
under authority owned by the project. Each actor brings claims about capability,
interests, cost, access, and availability. The coordinator must treat those
claims as inputs to test, not unquestioned facts.

For public contribution, people cannot hand a project access to a subsidized
agent subscription. That would break product terms and create a credential
nightmare. Instead, a contributor can ask their own agent to claim the highest
priority ready task matching their skills and interests. They continue steering
their agent and contribute the resulting work and evidence.

# Responsibilities

The coordinator should:

* query ready work from the Work Graph;
* match task requirements to an actor's declared and observed capabilities;
* respect owner policy, budgets, access boundaries, and concurrency limits;
* claim and renew the Work Graph's lease on behalf of the actor;
* assemble the smallest context package needed to begin;
* checkpoint progress before time or usage runs out;
* release work with a usable handoff; and
* record execution events for later analysis without filling the public DAG
  with raw telemetry.

# Personal mode

The first coordinator can be small. It only needs to know which of my agents are
available, what classes of work I trust each one to perform, and which ready
task is most useful. It should make resuming after a usage limit routine rather
than forcing the next session to rediscover the plan.

# Contributor mode

A public contributor should be able to request work using their own agent. The
request can include interests, skills, available tools, budget, and desired
complexity. The coordinator returns a task and a bounded context package. The
contributor's agent claims the lease, works in the contributor's environment,
and returns evidence or a proposed change through normal project controls.

This creates a more useful entry point than a stale "good first issue". The
work can match what the contributor wants to learn or support, while the graph
explains why it matters and which evidence will prove completion.

# First useful release

1. Wait until the Work Graph contains real ready tasks and reliable leases.
2. Define a portable description of task requirements and actor capabilities.
3. Add advisory matching for my own agents, with the final choice visible before
   claiming a lease.
4. Add checkpoints and clean handoff when an execution session ends.
5. Learn from completed, abandoned, and reassigned work instead of trusting
   model labels alone.
6. Add automatic matching within narrow owner-defined limits.
7. Test contributor-directed matching only after the personal and team modes
   work.

# Personal advisory pilot

On 28 September 2026, I ran the first personal pilot against the real Work
Graph ticket that governed the pilot. Two native Codex subscription sessions
handled the reasoning and checkpoint-resume work. The directly supervised
Codex session made the repository change. An OpenRouter-funded worker handled
the mechanical classification of measurements.

The router kept the API worker away from repository implementation. That worker
declared API access and metered-cost evidence, but not Git, repository write
access, or test evidence. This was the deliberate ineligible pairing in the
trial. A separate Claude Code route also failed its availability check because
its subscription OAuth session had expired. The attempt made no model call and
cost nothing. An installed executable is not proof that a worker is available.

I simulated a native-client usage limit after the reasoning worker returned its
first result. The coordinator wrote a Work Graph checkpoint, forked a new
native session, and resumed in 42.6 seconds without changing the ticket lease.
The successor retained the ticket, baseline counts, policy boundary, completed
analysis, and remaining work.

The API session then changed model and provider while keeping its session ID,
ticket context, and lease. Route-level records attribute all four billed
responses. One response was usable; three were empty or malformed. A fifth
request failed before inference because the provider credit left on the key
could not cover the requested output ceiling. The four billed requests cost
$0.002095945 in total.

## Comparison with manual routing

The baseline is the five coordinator tickets immediately before the pilot. All
five reached release through manually selected Codex subscription sessions.
Their lease histories contain eight gaps between a stopped or expired lease and
the next claim. Those gaps total 51.8 hours, with a median of 5.89 hours. Six
leases stopped for attention and three expired. The records do not say why each
attention stop occurred, so the pilot cannot honestly label them useful or
avoidable from the counts alone.

| Measure                     |                      Manual baseline |                       Advisory pilot |
| --------------------------- | -----------------------------------: | -----------------------------------: |
| Completion                  |                       5 of 5 tickets |        1 of 1 ticket report prepared |
| Recovery wait               |             51.8 hours across 8 gaps | 42.6 seconds for the simulated limit |
| Human attention stops       |                                    6 |                                    0 |
| Expired leases              |                                    3 |                                    0 |
| Checkpoint handoff recovery | Not recorded as a planned checkpoint |                               1 of 1 |
| Attributed metered cost     | $0, actual subscription cost unknown | $0.002095945 plus prepaid native use |

This is too small a sample to claim a general improvement. It did prove that a
durable checkpoint can cut the recovery gap without giving the coordinator
claim authority. It also showed that a provider accepting a request is not
enough. The coordinator must validate the response before it counts work as
complete.

## Policy changes from the pilot

* Check authentication and usable quota before showing a worker as available.
  Executable discovery alone is insufficient.
* Keep advisory mode as the default. The owner still confirms the proposed
  worker before claim.
* Write checkpoints before a known limit, with conclusions, evidence,
  assumptions, and the next exact action.
* Record the reason and outcome for every attention stop. Aggregate counts do
  not distinguish owner decisions from routing friction.
* Validate response content before recording completion. Empty or malformed
  output remains a failed request even when the provider billed it.
* Reserve the full request ceiling against both the session budget and the
  provider key's available credit before inference.

# Success

The coordinator succeeds when ready work spends less time waiting, actors receive
tasks they can finish, and an expired session does not destroy its progress. It
fails if it keeps cheap agents busy on low-value work or prizes subscription
capacity over project outcomes.

# Non-goals

* Owning project priority, dependencies, or completion state
* Receiving another person's subscription credentials
* Pretending a model name is a stable measure of capability
* Assigning every ready task when leaving capacity free is safer
* Removing the project owner's authority over what may run
