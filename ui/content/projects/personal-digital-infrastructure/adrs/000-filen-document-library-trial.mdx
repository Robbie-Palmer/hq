# Context

Personal documents accumulated across old computers, Google Drive, OneDrive,
and removable storage. Most files are now consolidated on one external hard
drive for deduplication. That drive is neither an offsite copy nor a convenient
way to retrieve a document from Android or another computer.

The replacement needs end-to-end encryption, macOS, Ubuntu, Android, and web
access. No device is authoritative. Each device may create, edit, rename, or
delete a document, and the other devices must converge without a manual upload
or download routine. Concurrent edits must remain recoverable as conflicts
rather than silently overwriting either version.

Supervised agents need a normal synchronized directory, a writable filesystem
mount, or an S3-compatible endpoint. Scheduled transfer commands fail because
they do not share sync state or resolve changes made on both sides. The cloud
library will be a synchronized working copy, not the only copy or the
independent backup.

Filen offers encrypted storage with desktop and mobile clients. Its
[CLI](https://docs.filen.io/docs/cli/) supports sync, mounting, WebDAV, and S3
access. This is a better match for Ubuntu and agent-operated file workflows
than a transfer-only command line.

# Decision

Trial Filen first with a representative copy of the consolidated document
library. Keep every Google Drive, OneDrive, and hard-drive source during the
trial.

Use nested folders, large files, common office formats, scans, Unicode names,
and deliberate duplicates. Test the macOS and Android apps, web interface, and
Ubuntu CLI. Exercise continuous two-way synchronization and agent writes
through a mounted filesystem or S3 endpoint. Do not substitute scheduled
uploads and downloads for a sync engine.

Promote Filen only after the trial proves:

* manifests before and after transfer match;
* files created or changed on macOS, Ubuntu, and Android reach the other
  devices without choosing a source device;
* renames and deletions propagate in both directions;
* concurrent offline edits from macOS, Ubuntu, and Android preserve every
  version or create explicit conflict copies;
* the client restores a deleted file and an earlier version;
* a clean Ubuntu machine can restore the test set with documented commands;
* an agent write through the mounted filesystem or S3 endpoint reaches the
  synchronized devices;
* unattended sync identifies failed paths and reconnects without duplicating
  or losing files; and
* the measured library fits the selected plan with growth headroom.

Filen currently lists 200 GiB at
[€1.99 per month or €19.99 per year](https://filen.io/pricing), and 500 GiB at
€3.99 per month or €39.99 per year. Recheck the checkout price, tax, and renewal
terms before accepting this decision.

# Alternatives

## Proton Drive

Proton Drive provides end-to-end encrypted file storage, polished mobile
access, and a CLI. Its Linux CLI transfers files but does not run a two-way sync
engine or expose a mounted filesystem. Wrapping upload and download commands in
a timer would still lack shared state for deletions, renames, and concurrent
edits. Reject Proton Drive for the working library even if Proton Unlimited is
economically compelling for Pass, VPN, or Mail.

## MEGA

[MEGAcmd](https://github.com/meganz/MEGAcmd/blob/master/UserGuide.md) provides
continuous two-way synchronization and allows multiple devices to synchronize
the same cloud folder. It also provides WebDAV and a writable FUSE mount on
Linux. Trial MEGA next if Filen fails. Its Linux FUSE support is still beta and
does not cover macOS, so the trial must use ordinary synchronized directories
where a mount is unavailable and must verify the Android edit-and-save path.

## Dropbox

Dropbox has an official [Linux sync daemon and
CLI](https://help.dropbox.com/installs/linux-commands), so agents can work in a
normal local directory. It has a more established mobile and desktop product
than Filen, but personal plans do not provide the same end-to-end encrypted
storage model. Keep it as the managed fallback if both encrypted candidates
fail their sync or Android tests.

## Cloudflare R2

R2 has an S3-compatible API, strong command-line tooling, and no egress charge.
It is an object store rather than a personal sync product. It has no first-party
document browser or offline mobile workflow. Keep it for project objects. The
working personal library needs a sync product.

## Google Drive or OneDrive

Both have polished mobile clients and already hold historical files. Google
does not provide [Drive for desktop on
Linux](https://support.google.com/drive/answer/2375082), so agent access would
depend on another client such as rclone. Dropbox is the cleaner privacy
compromise because it supplies its own Linux sync engine. Google Drive and
OneDrive remain migration sources until manifests and recovery tests prove the
move complete.

# Consequences

The first trial keeps end-to-end encryption while testing the broadest agent
interface of the candidates. The Android and macOS experience remains
unproven, and Filen's [roadmap](https://filen.io/hub/roadmap/) still includes
sync-engine and security-audit work. A failed trial loses no sole copy and
moves to MEGA, then Dropbox if the encrypted options cannot meet the mobile and
sync requirements. Proton's bundle price no longer affects the document-drive
choice.
