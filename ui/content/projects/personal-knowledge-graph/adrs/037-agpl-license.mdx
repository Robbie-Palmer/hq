# Context

[PDR 002](/projects/personal-knowledge-graph/pdrs/002-open-code-and-relicensing-authority)
licenses the project under AGPL-3.0 and requires a Contributor License
Agreement before contributed code merges. Pull requests need a consistent way
to record that agreement without making the maintainer compare signatures by
hand.

The agreement text needs one canonical source. Enforcement must identify the
GitHub contributor, block an unsigned change, and preserve an auditable result
on the pull request.

## Alternatives Considered

* **Manual review**: Requires no application access, but every first
  contribution needs a maintainer to compare the contributor and agreement
  records. That is easy to perform inconsistently.
* **A custom GitHub Action**: Keeps the check in the repository but creates a
  local identity, storage, and maintenance problem for a standard workflow.
* **CLA Assistant**: Uses the GitHub identity and pull-request check, records
  signatures, and can point at the canonical agreement text.

# Decision

Use [CLA Assistant](https://github.com/cla-assistant/cla-assistant) to enforce
the agreement required by PDR 002. Configure it to use the
[canonical agreement](https://gist.github.com/Robbie-Palmer/94798c38da1307cfc60ab98dc0984818)
and require its pull-request check before merge.

# Consequences

### Pros

* Contributors sign with the same identity they use for the pull request.
* The merge check gives reviewers one visible enforcement result.
* The agreement text stays outside the application code and can remain the
  single source used by the service.

### Cons

* Enforcement depends on a third-party GitHub application.
* Contributors must complete an extra step on their first pull request.
* A service outage or identity mismatch can block an otherwise valid change and
  require maintainer investigation.
