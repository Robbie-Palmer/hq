# Vision

We wanted to bridge the gap between physical retail and online deals. The goal was to empower users to walk into a store, take a photo of a product (or "circle to search" on their screen), and immediately find the best online price in real-time with minimal data entry.

# Problem Statement

* **Friction**: Traditional search requires users to type product names or scan barcodes, which is slow and error-prone in a physical store environment.
* **Visual Complexity**: Products often have visual distinctiveness that is hard to describe in text keywords.
* **Real-time Demand**: Users need instant feedback to make a purchasing decision while standing in the aisle.

# Methodology

I architected a multi-modal search engine using **Weaviate** as the core vector database:

* **Multi-Modal Embeddings**: Configured Weaviate to index both product text descriptions and product images into a shared vector space.
* **Visual Querying**: Allowed users to use an input image (from camera or screenshot) as the search query.
* **ML Pipeline**: Built a **Python** pipeline managed by **DVC** to evaluate different embedding models and iterate on search relevance.
* **Integration**: Built the search integration in **TypeScript**, with a **Swift** iOS app, a **Kotlin** Android app, and a **SvelteKit** web app for submitting image queries and rendering results.

# Search data flow

Product catalogue images and descriptions entered separate embedding paths, then Weaviate stored their vectors in
a shared index. The Swift iOS app, Kotlin Android app, and SvelteKit web app submitted image queries and displayed
the ranked matches returned through the TypeScript search integration.

In equivalent text:

1. Product images produced image embeddings. Product descriptions produced text embeddings. Weaviate indexed both
   types of vector in a shared search space.
2. The Swift iOS app, Kotlin Android app, and SvelteKit web app each passed image queries into the TypeScript search
   integration.
3. The search path converted each query image into a vector and compared it with the shared Weaviate index.
4. Similar product candidates went through relevance ranking. The TypeScript integration returned the ranked
   matches to the requesting client.
5. Separately, a Python pipeline versioned with DVC evaluated embedding-model variants and search relevance. The
   team used those results to iterate on the search system.

# Impact

* **Zero-Shot Discovery**: Users could find products they didn't know the name of, purely by visual similarity.
* **Seamless UX**: Removed the friction of text entry, making deal-finding accessible in seconds.
* **Cross-Platform**: Swift, Kotlin, and SvelteKit clients brought the same image-search flow to iOS, Android, and the web.
