## Context

[PDR 002](/projects/work-graph/pdrs/002-require-deliberate-parent-termination)
requires a deliberate terminal decision after the last child finishes. The
domain model uses the same `released` and `cancelled` words in current
work-item state, projected stage, and historical lease outcomes. Their storage
and transition roles must remain distinct.

[ADR 000](/projects/work-graph/adrs/000-flexible-work-item-graph) makes an open
parent wait while it has non-terminal direct children. Removing the last child
blocker must update readiness without implying a terminal transition.

## Decision

When the final direct child terminates, recompute the parent's normal readiness
predicates. Keep its lifecycle open. A later release or cancellation must run
as an explicit, lease-fenced transition on the parent.

Use `released` and `cancelled` as the canonical terminal work-item values.
Stored lifecycle and projected board stage share those values because they
describe the same current condition.

Keep lease outcome as a separate historical type. A lease outcome of
`released` or `cancelled` records how that lease ended and identifies the lease
that performed the transition. It does not determine current work-item state
independently.

Define the terminal values once in the domain package, then compose the
lifecycle and stage vocabularies from that definition. Reuse the strings in
lease outcomes while retaining their separate schema and event meaning.

## Consequences

The parent can return to the ready queue without a hidden lifecycle write.
Release and cancellation remain attributable to one current lease and fencing
epoch.

The read model must distinguish a ready parent from a released parent even when
all children are terminal. Event consumers must also distinguish current
lifecycle from the reason a historical lease ended.

Using the same strings across the three types keeps projections consistent but
requires tests that prevent lease history from becoming a second source of
current state.

## Migration note

The 1 November 2026 PDR migration moved the deliberate-completion policy into
PDR 002. This ADR keeps the original lifecycle, stage, lease-outcome, and
readiness architecture. No transition changed.
